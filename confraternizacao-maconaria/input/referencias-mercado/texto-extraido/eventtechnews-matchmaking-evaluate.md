Quick answer: judge a matchmaking tool by whether the right people meet at a time and place that works, not by the size of its algorithm. Write down the meetings you want, check attendee mix, ask what data drives suggestions and who can contact whom. Run the same test journey with each supplier and count **meetings held**, not clicks.

## Start with the meeting you want

Write meetings that make the event a success (buyers↔suppliers, investors↔startups, mentors, peers). Formats differ: 1:1, sponsor, one-to-many, speed networking, theme-based. Each needs different profile questions and contact rules.

| Model | How it works | Suits | Example |
|-------|--------------|-------|---------|
| Open matchmaking | Suggestions → request/accept | Conferences, community | Whova (interests, location, affiliation) |
| Pre-scheduled | Preferences → organizer builds diaries | Hosted buyer, investor | Grip MustMeet |

## Right people present

Matchmaking cannot create buyers who did not register. Check mix early; weak profiles → weak recommendations.

## Data that feeds recommendations

Ask in writing: which profile answers / behaviors; data carry-over to next event; opt-out without losing event access; who at supplier sees data and retention.

## Control who can reach whom

Gated networking by ticket type (Brella, Whova tiers, Grip permissions). Protect speakers/VIPs. Test report/block on phone.

## Scheduling and locations

A match is not a meeting until time + place. Calendar sync, time zones, reminders, cancel/late. Table assignment / meet-at-booth. Buffer between slots.

## Measure meetings, not clicks

Count: requested / accepted / held; rated useful; no-shows; post-event follow-up. Sponsor renewals need meeting evidence.

## Demo script (same journey each vendor)

1. Two people register (buyer + seller)
2. Complete profiles including matchmaking questions
3. Review recommendations and ask why
4. Request, accept, move, cancel a meeting
5. Try blocked contact + report a message
6. Organizer view + export
