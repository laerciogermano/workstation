·Introdução

"Nothing is permanent, except change." – Heraclitus, c. 535 – c. 475 BCE

O Flow é um paradigma visual para desenvolvimento orientado a serviços. Ele busca o desacoplamento em nível de serviço em todas as chamadas, de modo que cada componente seja uma camada substituível, com uma linguagem onipresente e representações visuais concretas. Desenhado para software, os princípios valem para qualquer área.

No mundo real, objetos interagem por leis físicas comuns e podem ser trocados por outros que cumpram função equivalente. No software tradicional, muitos comportamentos não são compatíveis com esse desacoplamento — por exemplo, não dá para injetar uma função assíncrona onde se espera uma síncrona. No Flow tudo é homogêneo: entradas são injeção de dependência e vice-versa, então parâmetros são camadas — comportamento e/ou dado — substituíveis.

"A picture is worth a thousand words." – Confucius, 552–479 BCE

Cada parte elementar do software também vira uma figura. 1Um fluxo de execução é feito de dados e funçõesA flow of execution consists of data and functions.

O fluxo mais simples tem um dado (quadrado) e uma função (barra arredondada). A função fica na linha, o dado aparece no estado em que existe.

2Dado é uma unidade de informaçãoData is a unit of information.

O dado é o quadrado. Vazado = abstrato (ninguém no fluxo o produz: vem de fora). Cheio = concreto (tem valor ou é produzido por uma função concreta).

3Um estado pode ter n dadosA state can have n data.

O estado é a coluna s0…sN; abaixo dele ficam os dados que existem ali. Dois dados podem entrar juntos num estado, ou nascer de funções diferentes no mesmo estado.

4Função é uma unidade de mudança de estadoA function is a unit of state change.

A barra arredondada é a mudança: antes dela vale o estado s0, depois dela o s1. Aqui a função devolve a.

5Uma função tem n endereços de entrada e n de saídaA function can have n input addresses and n output addresses.

Entrada fica à esquerda da barra, saída à direita. Mais de um dado na mesma ponta vira um cubo (um objeto com campos).

6Funções e dados podem ter endereços concretosFunctions and data can have concrete addresses.

Endereço concreto = existe de fato no fluxo: a função tem executor (lib do navegador ou arquivo) e o dado tem valor. É a barra cheia e o quadrado cheio.

7Funções e dados podem ter endereços abstratosFunctions and data can have abstract addresses.

Endereço abstrato = só o nome, sem executor nem valor: barra vazada e quadrado vazado. Pode ser preenchido por uma IA, uma pessoa, ou quem chamar o fluxo.

8Uma função recebe endereços abstratos de dados e funções como entradaA function can receive abstract addresses of data and functions as input.

Entrada é injeção de dependência: tanto o dado quanto a função chegam pelo context. Em ambos os casos o endereço é abstrato (vazado).

9Uma função devolve endereços concretos de dados e funções como saídaA function can return concrete addresses of data and functions as output.

A saída é o que a função entrega ao estado seguinte: um dado ou o endereço de outra função.

10Funções podem conter outras funções em sequênciaFunctions can contain other sequential functions.

A função f vira uma faixa (composição) e as filhas ocupam estados consecutivos: f2 só começa quando f1 termina.

11Funções podem conter outras funções em paraleloFunctions can contain other parallel functions.

Em paralelo as filhas ocupam o mesmo estado: as duas barras ficam na mesma coluna.

12Funções podem conter estruturas de seleçãoFunctions can contain selection structures.

A seleção é a faixa if (triângulo amarelo). O que está dentro só roda quando a condição é verdadeira.

13Funções podem ter estruturas de repetiçãoFunctions can have loop structures.

A repetição é a faixa for (↻). O corpo roda uma vez por item; a variável do for (item) vale só ali dentro.

O PDF escreve a repetição como a função chamando a si mesma. O editor desenha a repetição com o bloco for … of, e o código gerado usa for.

14Endereços que se conhecem fazem parte da mesma camadaAddresses that know each other are part of the same layer.

Quando tudo o que f usa é importado (f1 e f2 são arquivos, a tem valor), nada vem de fora: só há barras e quadrados cheios. As funções f1.ts e f2.ts aparecem ao lado.

A chamada recursiva f({ ...context, a }) do PDF aparece aqui como um passo g dentro do if.

15Endereços que não se conhecem estão em camadas diferentesAddresses that do not know each other are in different layers.

Agora a e f2 não são importados: chegam pelo context. Ficam vazados (abstratos); só f1 é conhecida (cheia). Cada endereço abstrato é uma fronteira entre camadas.

16A entrada forma uma camada de contextoInput forms a context layer.

Tudo o que a função pede e não conhece — os quadrados e barras vazados da esquerda — forma o contexto: a camada que falta para completar o fluxo.

17Uma camada é uma unidade substituívelA layer is a replaceable unit.

Como a camada é só um endereço, qualquer coisa com o mesmo contrato a substitui. À esquerda f2 é abstrata; à direita ela foi trocada por uma função concreta (Math.round) e a ganhou valor.

18Camadas diferentes podem ser combinadas em novas camadasDifferent layers can be combined to form new layers.

A camada A pede a; a camada B entrega a. Juntas formam a camada AB, em que a já é um quadrado cheio.

19A execução do fluxo acontece quando a camada está completaThe flow execution occurs when the layer is complete.

Enquanto houver endereço vazado, o fluxo não executa. Quando tudo é cheio, ele roda de s0 a sN.

20Uma camada com contexto completo equivale a um novo contexto para outra camadaA layer with a complete context is equivalent to a new context for another layer.

O resultado de uma camada completa (c) é só um dado a mais: serve de entrada de outra camada (g), e assim camadas se encadeiam.
