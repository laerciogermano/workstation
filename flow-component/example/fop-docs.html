1Visão geral

O fluxo é uma árvore de funções e blocos. O editor aplica comandos sobre um projeto imutável, calcula o layout em estados (s0…sN), desenha tabela e diagrama e gera TypeScript/JavaScript executável.

comando ──► apply(projeto, comando) ──► projeto novo ──► Store.subscribe ──► render()
                    │                                              │
             histórico (past/future)                  layout(flow) ──► tabela HTML + plano SVG
                                                       generate(projeto) ──► TS/JS ──► Worker (Run)

2Modelo

type AgentKind = "maquina" | "ia" | "pessoa" | "arquivo";
interface Contract { ins: string[]; outs: string[]; optional?: string[] }
interface Agent    { id: string; kind: AgentKind; name: string; tasks: string[]; contracts?: Record<string, Contract> }

interface Fn {
  t: "fn"; id: string; title: string;
  agent: string | null;            // Source: id do agente ou "file:<arquivo>"
  resp: string | null;             // pessoa responsável (quando agent é IA)
  ins: string[]; outs: string[];
  kids: Node[]; par: boolean;      // filhas · roda junto da anterior
  args?: Record<string, string>;   // entrada → expressão
  file?: string;                   // só na função raiz
}
interface IfB  { t: "if";  id: string; test: string; kids: Node[]; elseKids: Node[] }   // elseKids = [] → sem else
interface ForB { t: "for"; id: string; v: string; coll: string; kids: Node[] }
interface TryB { t: "try"; id: string; kids: Node[]; catchKids: Node[] }
type Node = Fn | IfB | ForB | TryB;
interface Project { name: string; flows: Fn[]; agents: Agent[]; seq: number }
InvarianteGarantia
Id único e estável (IDR)nextId(p) incrementa seq; ids nunca são reutilizados; renomear não muda o id; referências usam o id
Nomes não vazios (máx. 80 em título e arquivo)cleanText / cleanName → FlowError("invalid")
Raiz não tem irmãos nem estrutura em voltaisRoot; comandos falham com root
Arquivos com nomes distintosrenameFile recusa colisão
Lib: ins/outs vêm do contratoapplyContract ao trocar lib/task; mantém valores de mesmo nome

Consultas: locate(p,id) → { node, list, index, parent, slot, flow }; walk, fnsOf, kidsOf, altKids (catch/else), filesOf, flowFile (f.file ou slug(title).ts), statesFor (dados disponíveis antes de uma função + variáveis de for que a cercam).

7Valores e condições

Valor = expressão TypeScript em Fn.args[entrada]. Rascunho (args.ts): ArgType ∈ text · number · boolean · ref · expr · object; buildArg → expressão; inferArg → rascunho. exprIdents(expr) devolve os identificadores livres (ignora strings, chaves de objeto e .campo). isDataRef(expr) = só referência a dado (total, xs[0]); true/false/null/undefined e demais literais/expressões não são ref — o codegen declara const text = false. No plano: ao lado da marca só o nome; o valor (text = false, field1 = "…") fica só no rodapé do estado.

{ field1: "x" }objeto → cubo no estado + campos com valor

Condição (cond.ts): cláusulas esquerda op direita ligadas por && / ||; buildCond / inferCond; splitTop divide só nos conectores de nível mais alto.

9Layout

layout(flow, { closed }) → Scene, sem DOM.

interface Row   { kind: "fn"|"block"|"catch"|"else"; id; node; depth; s: number; e: number; last: number; leaf: boolean; closed: boolean }
interface Scene { rows: Row[]; nSteps: number; span: Map<string,{s,e}>; maxDepth: number; leaves: Row[] }
  • Folha: s = par ? prev.s : step; step = max(step, s+1).
  • Composição: s = início; e = fim da última filha; closed não emite as filhas.
  • Bloco: e = fim dos filhos. Catch/else: linha própria com s = max(step, next − count), terminando com o bloco.
  • nSteps = nº de colunas; leaves = folhas fora de catch (usadas em links()); maxDepth dimensiona a tabela.

Geometria (view.ts): origem do diagrama G.OX; coluna G.W (maior quando o nome fica dentro da barra); linha G.RH = 34; recuo da tabela G.IND = 14 por nível (×2 no padding). No plano (direita), cada nível tem barra lateral de largura IND + planGutter. tableWidth(sc, p) = chrome + maxlinhas(recuo + texto + menu).

export async function applyCoupon(state: State): Promise<State> {
  // expected inputs (from another layer): price, percent
  const { round, log } = state as Record<"round" | "log", Fn>;
  const { price, percent } = state as Record<string, any>;
  const value: unknown = price * (100 - percent) / 100;
  const { total } = await round({ ...state, value });
  if (percent > 0) {
    const text: unknown = `Coupon ${percent}% off: ${price} -> ${total}`;
    await log({ ...state, text });
  }
  return { total };
}
export const wrappers: Record<string, Fn> = {
  round: async (state) => { const { value } = state; return { total: await Math.round(value as never) }; },
  log:   async (state) => { const { text } = state;   await console.log(text as never); return {}; },
};
// run: await applyCoupon({ ...wrappers, price, percent });

11Execução

runInWorker(code, onEvent) → { stop() }. O Worker (criado de um Blob) recebe { code } e executa execute(code, emit): o código roda como corpo de função assíncrona com um console próprio.

type RunEvent =
  | { type: "log";   level: "log"|"info"|"warn"|"error"|"debug"|"table"|"system"; text: string; t: number }
  | { type: "done";  ms: number }
  | { type: "error"; message: string; ms: number };
  • Primeiro evento ≠ log (done/error) encerra o Worker; stop() o termina.
  • t = ms desde o início. O texto logado é espelhado no console do DevTools.
  • Sem DOM no Worker, mas não é sandbox de segurança: fetch e demais globais existem (CORS vale).
  • Abstratas e pessoas rodam como stubs: validam o fluxo, não produzem resultado real.

14Erros e restrições

SituaçãoResultado
Nome vazio / > 80 caracteres (título, arquivo)invalid
Id inexistentenot_found

renameFile para nome existenteinvalid
addElse em if que já tem elseinvalid
Editar E/S de função de libbloqueado (contrato); só a saída se renomeia

Nomes de entrada: não use nomes de tarefas de lib (min, max, round, log…) nem state: colidem com o código gerado.
