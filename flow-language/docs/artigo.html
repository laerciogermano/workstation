01

O que é Flow

O que o Flow é: uma linguagem visual que transforma código em visão.

  • linguagem de programação visual
  • orquestrador de processos (similar a n8n)
  • visão logística de todos os fluxos
  • código → visão (facilita análise)
  • estrutura física do software / plano das ideias
  • epígrafes: panta rei (Heráclito); “a picture is worth a thousand words”
  • Flow nasce de “panta rei”: escrever Flow é vigiar a intenção (Logos driver design)med.
  • Flow como linguagem da estória: o plano das mudanças, isomórfico à linguagem e ao pensamentomed.

02

Por que Flow (paradigma)

O paradigma: olhar a ordem dos eventos, não os objetos.

  • olhar a ordem dos eventos, não os objetos
  • menor unidade: mudança de estado (mônada)
  • eternos (verbo) × mutáveis (estado)
  • ouro está no que e no quando, não no quem
  • roteiro abstrato → concreto (sem sujeito como substância)
  • contraste com OO: OO acopla dado + comportamento; Flow separa função e dado
  • objeto = acúmulo de atributos entre verbos/fluxos (ex.: bola de boliche)
  • Duas substâncias: estado/objeto (visível, mutável) × movimento/verbo (invisível, eterno)med.
  • Erro ontológico de Aristóteles: unir característica e mudança deu a OOP e o MERmed.
  • História = unidade de ação: estado inicial → verbo → estado final; histórias se repetem, mudam os elementosmed.
  • Heráclito (muda) e Parmênides (constante) unificados; forma é o espaço, matéria é o que preenchemed.
  • Declarativo × imperativo (pendência anotada para o artigo)med.

A linguagem

Funções, estados, objetos, estruturas e camadas

03

Funções

A unidade de mudança de estado, com n entradas e n saídas.

  • unidade de mudança de estado
  • n entradas e n saídas (endereços)
  • podem conter outras (sequência, paralelo)
  • componentes substituíveis / desacoplamento em nível de serviço
  • Mônada = estado + movimento; verbo = estória; história = verbo acionadomed.
  • Toda mônada tem sua antagônica: cai(João) ↔ levanta(João)med.
  • Movimentos com os mesmos estados inicial e final são correspondentes (porta e tampa: abrir/fechar)med.
  • Mesmo ato pode estar contido em mônadas diferentes; mônadas compatíveis se relacionam (sequencial ou paralelo)med.

04

Estados

Dados, entradas, saídas e contexto: estado como fatos condensados.

  • dados
  • input
  • output
  • estado / contexto
  • estado = conjunto de fatos condensados
  • todo ato liga estado inicial → movimento → estado final
  • Todo estado é precedido da execução de um verbo; todo verbo gera um novo estadomed.
  • Atenção ao side effect ao passar objeto de dados por referênciamed.
  • Pensar como stateless (exemplo do porteiro): não guardar estadomed.

05

Objetos

O objeto como ponte cognitiva, e seu lugar entre verbo e estado.

  • seres com dados e funções (visão legada / ponte cognitiva)
  • coleções, posição
  • hashmap (chave–valor)
  • no Flow: objeto não é ator; preenche espaço entre verbo e estado
  • atributos com responsabilidade por movimento
  • Objeto = acúmulo de características acopladas usadas em mônadas diferentesmed.
  • Modelagem relativa ao movimento: o acúmulo de movimentos a uma referência define o objetomed.
  • Identidade polimórfica: valores diferentes para perspectivas diferentes (arquétipos)med.
  • Menos acoplamento, mais coesão por objetivo: papéis com uma única funçãomed.

08

Files (Layers) e endereços

Todo dado, função e abstração tem um endereço; camadas se conhecem.

  • todo dado tem um endereço
  • toda função tem um endereço
  • toda abstração tem um endereço
  • quem se conhece = mesma camada; quem não = camadas distintas
  • entrada = camada de contexto; camada completa → execução
  • inputs como injeção de dependência / parâmetros substituíveis
  • O endereço surge na contraposição dos seres; perspectiva é endereçomed.
  • Todos somos o mesmo, só mudamos de endereçomed.
  • Anotar cria referência: o que não se anota perde o endereçomed.

09

Sólidos × abstratos

O que tem endereço físico e o que ainda é espaço a preencher.

  • sólido: tem endereço físico
  • abstrato: não possui endereço físico
  • no plano das ideias, elementos viram planos
  • funções podem receber endereços abstratos e devolver concretos
  • Forma é espaço/molde abstrato; matéria preenche; identidade está na forma (navio de Teseu)med.
  • Para todo espaço, preenchimento; para todo preenchimento, novos espaçosmed.
  • Linguagem, pensamento e realidade são isomórficosmed.

11

Técnica Flow (método)

Escrever todo dia sobre a tarefa: o método para manter o plano.

  • escrever diariamente sobre o tema/tarefa
  • documento cresce → engajamento e retorno ao estado
  • diário cronológico para retomar concentração
  • vigiar a intenção (Logos driver design)
  • focar no plano, não em pessoas
  • Escrever Flow: autenticidade da criação, centralizar a atenção, conseguir recursosmed.
  • Pensar sempre na intenção; a ação vem da intençãomed.
  • Trabalhar em cima da obra, sem desperdiçar tempo com rascunhosmed.
  • Escrever, clusterizar, refinar; não se exaltarmed.
  • Gerar referências enquanto falamed.
  • Não comentar motivos: ordenar o ato (e0 → e1)med.
