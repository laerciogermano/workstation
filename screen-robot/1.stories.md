# Stories — screen-robot

**Por quê:** lista visual das histórias (US) e como cada uma funciona.  
**Épicos:** [`2.epics.md`](2.epics.md) · **Visão:** [`README.md`](README.md).

## Histórias

| ID | Estória | Como funciona |
|----|---------|---------------|
| US-01 | Provisionar um agente | Pelo **nome**: se for novo, cria **AVD/emulador** dedicado, resolve serial e conclui com ADB `device` + boot; se o nome **já existir**, anexa ao runtime existente **sem** criar outro. Vários nomes ⇒ vários agents em paralelo (mais pesado). |
| US-02 | Evento de boot | Após serial online, listener (com timeout) espera o sinal de boot; devolve “boot ok” como pré-condição para instalar/abrir apps. |
| US-03 | Evento de app aberta | Recebe package (e activity opcional) e espera a app em foreground antes de gestos/estabilidade — evita operar tela errada. |
| US-04 | Evento de tela estável | Com app em foreground, espera estabilização do **frame** (imagem); libera captura, OCR/extração e operações confiáveis. |
| US-05 | Evento de mudança de frame | Compara o **frame/imagem** atual com o anterior (hash/diff visual); quando a tela muda, devolve frame atualizado — base para OCR e automação sem dump ADB. |
| US-06 | Instalar APKs | Para cada app em `device.config.json`, lê package/versão, baixa APK/XAPK e instala via `adb install` (ou equivalente). |
| US-07 | Abrir aplicativo | Launch de package/activity no device até a app em foreground; entrada para gestos e captura de frame. |
| US-08 | tap | Toque em x,y ou bounds obtidos da **visão/OCR** sobre a imagem; espera a UI refletir a ação no próximo frame. |
| US-09 | type | Digita a partir da **imagem do teclado** no frame: OCR localiza cada tecla (dígitos/caracteres); região opcional `{ x, y, width, height }`; digita **só com tap** em cada tecla. Sem `input text` / ADBKeyboard. |
| US-10 | scroll | Swipe/scroll por direção, distância ou bounds; novos conteúdos aparecem no frame para re-OCR. |
| US-11 | Capturar frame (screenshot/câmera) | Obtém a **imagem da tela** (screenshot ADB, stream ou **câmera** em device real) e grava no path; **única entrada** para OCR, match e extração. |
| US-12 | Resgatar coordenadas x,y a partir de uma imagem | Match de template / visão no frame; devolve x,y e confiança — alvos sem texto OCR ou com ícone visual. |
| US-13 | Extrair textos | Sobre o **frame**, **OCR** extrai textos + bounds → lista plana `{ type: "text", text, bounds, center }`. Única extração de UI (sem ícones/listas/imagens). Sem árvore DOM / sem uiautomator. |
| US-17 | Salvar sessão | Serializa estado em memória e grava no path da sessão. |
| US-18 | Remover sessão | Apaga arquivo de sessão e limpa contexto no runtime. |
| US-19 | Recuperar sessão | Lê o arquivo e reaplica device, apps, etapa e paths no runtime. |
| US-20 | Resgatar agente existente | Coberto por `provisionEmulator` com o **mesmo nome** de um agent já criado: localiza o AVD/emulador, reconecta o serial ADB e devolve `{ serial, kind, provisionedAt, bootCompleted }` (boot ok) **sem** criar outro emulador. |
| US-21 | Abrir scrcpy (espelhar tela) | Com `serial` online, `openScrcpy({ serial, … })` sobe o **scrcpy** nesse device: janela para **visualizar e operar** o Android (tocar, digitar, rolar) em paralelo à automação Node. |
| US-22 | Mascarar identidade do aparelho | Em **qualquer vendor** de runtime, o Android aparente para apps **não** expõe o fingerprint/nome do ambiente de automação; apresenta marca/modelo de aparelho de mercado (`ro.product.*` ou equivalente). |
| US-23 | Buscar elemento(s) por texto (similaridade) | `findByText(serial, query)` **encapsula** `extractElements` (OCR interno); não recebe lista. Devolve elementos **lado a lado** cujo texto (juntos) está **contido na string maior** (query), com **score** elevado — ex. query `"Sign in with Email"` → `Sign` + `in` + `with` + `Email`. |
